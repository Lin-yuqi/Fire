## Agent execution policy

This is a personal learning project.

- You may use relevant skills when they clearly improve correctness or design quality.
- Prefer lightweight use of skills; do not automatically chain multiple skills unless necessary.
- Prefer a single-agent workflow for normal coding tasks.
- Spawn subagents only when parallel work has clear value.
- Keep the scope close to my request and avoid unnecessary refactors, documentation, or new files.
- For small changes, prefer direct implementation plus relevant tests.
- Use `apply_patch` first for repository edits so Codex can show the changed-file review card. If the tool is blocked, explain the error before using another edit method.
- Before starting a large workflow involving multiple skills, multiple subagents, or substantial extra work, briefly tell me what you plan to do and why.
- Optimize for learning value and engineering quality, not maximum process rigor.
